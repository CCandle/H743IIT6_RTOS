# Refactor Rules

- 目录命名首字母大写，Cube 生成目录保持不动；自定义层次：OS/、DriversExt/、App/ 下按功能分组。
- Cube 生成文件只在 USER CODE 区调用自定义接口，不在其中编写业务逻辑；业务逻辑放在自定义目录。
- CMake：优先声明基础库（OS、DriversExt、LCD_Drivers），再构建 App；新增子目录时同步添加 include 路径。
- 驱动封装：厂家代码原样保留；通过 C++ 包装类（如 `LT768Driver`）暴露受控接口，任务只依赖包装层。
- 内存/MPU：TCM 开启需设置 SZ；非 DMA 缓冲可缓存，DMA 缓冲需 cache 管理或放在非缓存段。
- 注释规范：公共接口/复杂逻辑使用 Doxygen 风格（`/** ... */`）；易变逻辑补充简明注释，避免冗余。
- 提交流程：每步重构（目录调整、接口封装、逻辑迁移）单独提交，保持可编译；变更 `.ioc` 时与相关代码一起提交。
